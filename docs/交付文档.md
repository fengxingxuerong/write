## 一、项目概述

墨匠是多模型协作的长篇小说生成流水线：不同 LLM 各司其职（规划/写作/编辑/标题/审校/终审等），配合本地零成本质检（番茄评审器、黄金三章体检、爽点曲线、签约可行性报告），从大纲到成书全链路自动推进，支持断点续传与质量闭环。

**定位声明（合规）**：墨匠定位为 **AI 辅助创作工具，作者主权、人工把关，不是全自动代笔**。工具链路为 **生成初稿 → 机器门禁 → 人工试读复核 → 签约评估**——流水线与门禁产出的是供作者审阅的初稿与质量证据，成稿发表/投稿前须由作者完成人工复核与修改（对应 2026 年平台「AI 占比红线、禁纯 AI 直出正文」治理要求）。

**核心目录**：
- `scripts/novel_pipeline.py` —— 多角色协作流水线主程序（本次交付主改动文件）
- `scripts/generate_novel.py` —— 单模型生成器 + 共享函数库（prompt/质检/JSON 解析）
- `scripts/fanqie_review.py` —— 番茄过审评审器（本地规则，零 LLM 成本）
- `scripts/md_projection.py` —— 随书 Markdown 投影（当前状态/伏笔台账/控制面，jsonl 的人读视图）
- `scripts/qa_scan_existing.py` / `ab_compare.py` / `run_quality_test.ps1` —— 成书扫描 / A/B 对比 / 一键实测
- `scripts/qa_semantic_check.py` —— 投前语义硬伤检测器（人称 / 称谓 / 题材内容 / 关系张冠李戴，关卡 1-4 纯规则零 LLM 成本）
- `scripts/run_smoke_gate.py` —— 端到端冒烟门禁（编译检查 → 3 章小样全链路 → 自动验收十七项），见「三·八」
- `scripts/watchdog_novel.ps1` / `watchdog_pipeline.ps1` —— 长跑守护（进程死亡且书未完成自动断点续跑）
- `scripts/test_generate_quality.py` / `test_pipeline_reliability.py` / `test_md_projection.py` / `test_world_landing.py` —— scripts 侧单测（CI `unittest discover` 65 例）
- `data/generated/` —— 成书产物（jsonl 进度 / txt 成书 / 评估卡 / 终审卡 / 上架包 / Markdown 投影）
- `lib/` + `test/` —— Flutter 客户端（113 个 Dart 源文件 / 89 个测试文件），交付内容见「三·九」

> 注：早期一次性端点探针脚本 `probe_roster_20260912.py` / `probe_roster_r2_20260912.py` 与 8 角色冒烟脚本 `smoke_roles_20260912.py` **未入库**（临时产物，仓库中不存在，`git log --all` 亦无跟踪记录）。其结论已完整沉淀在本文档「二、端点可用性」与「六、验证记录」，需要复现须按本文档「六、验证记录」的口径重写探针。

## 三、终审官：三级质量权力（本次核心交付）

收官后 Phase 3.5 自动执行，流程：

```
终审第 1 轮（pro 通读：全书结构化摘要 + 首章/末章/最低分章样本正文）
   ↓ 总分 < 打回线（默认 75，--chief-rewrite-threshold）
【权力一·修章】从 top_issues 提取被点名章节（≤ --chief-rewrite-max 章，默认 3）
   → 编辑链定向重写（问题+证据+修改方向注入，只修问题不动剧情，字数只多不少）
   → 该章重新评审并同步分数
   ↓
终审第 2 轮（二审，以其为准；重写后总分仍会如实给低分，不放水）
   ↓ 二审仍 < 打回线（且 --no-chief-structure 未开）
【权力二·结构打回】交规划官裁决（structure_fix_prompt）
   → 规划官增补收尾章（≤ --chief-structure-max 章，默认 2）
   → generate_appended_chapter 走完整角色链生成（规划→写手→编辑→标题→评审门→状态/伏笔）
   → 终审第 3 轮确认，终审卡记录完整轨迹
```

- 输入证据包：逐章指标表（字数/评审分/钩子/AI味/问题数）+ 跨章状态清单 + 未收伏笔台账 + 三段样本正文
- 输出：JSON 总评（总分 / 六维：开篇钩子·节奏曲线·人物弧光·爽点与期待感·伏笔回收·结局力度 / 带证据问题清单 / 可执行修改建议 / 商业对标）
- 解析鲁棒性：严格失败自动修复解析；规划官裁决解析失败自动重试一次，**绝不把解析失败误报成"判定无需加章"**
- 产物：`<书名>.终审卡.txt`（终审轨迹含修章轮次与结构轮次）+ jsonl `type=chief_review`

**结构打回真书验证（《断脉逆命诀》，2026-09-13）**：第 1 轮 71 分 → 规划官裁决「6 条核心伏笔全悬空，需补章」→ 增补第 7 章《玉裂藏珠》3292 字（评审 84 分达线）→ 三审 64 分。**机制全程跑通，但暴露指令执行衰减**：写手未兑现"回收至少 2 条伏笔"指令（章末写成开脉突破悬念，台账 6 条仍全 open）。已落地「回收清单打勾」v1 治理（必兑现清单注入 + 逐条校验 + 未兑现定向补写，单测 3 项 PASS，真书验证待配额恢复），详见已知问题。

## 三·五、大纲终审官：写前守门（第 11 角色，同日晚间新增）

**动机**：终审官二审（《断脉逆命诀》）证明结构级问题（第 1 章伏笔全悬、末章停"前夕"无结局）单章重写治不了——根子在上游大纲，等收官才发现为时已晚。守门前置到写第 1 章之前，成本一次性、收益全书级。

```
Phase 1 规划官出大纲 → concretize_world → 原始大纲落盘（崩溃恢复依据）
   ↓
Phase 1.5 大纲终审官（pro K2 主 → glm K1 备，max_tokens 8000）
   ├─ pass ✅ → 放行，进入逐章生成
   ├─ fail ❌ → 采纳修订版大纲（字段兜底合并 + 再过 concretize_world）
   │            → 修订版以新一条 type=outline 追加（load_state last-wins，续传安全）
   └─ LLM 挂/解析失败 → 放行原大纲（守门岗不阻塞生成）
```

- **检查清单**（真实成书教训沉淀为硬规则）：伏笔分布（单章新埋 ≤2、第 1 章限 1-2 条、总数 ≤ 章节数×0.8）、末章必须有结局（禁"前夕态"）、单章新设定 ≤2 个、钩子链类型不连续重复、主线动机-目标-障碍-代价闭环、无连续 2 章纯铺垫塌陷
- **审查留痕**：`type=outline_review`（pass/overall/issues/adopted）写入 jsonl
- **开关**：`--no-outline-review` 跳过守门（默认开启）
- **验证**：py_compile 通过；符号冒烟 4 项全过（链路结构/setup_keys/prompt 生成/argparse）；待下一本新书跑 Phase 1 真书验证守门出分与修订采纳

## 三·八、投前质检五关 + 冒烟门禁十六项（2026-09-23 落地，2026-09-26 扩至十六项）

**动机**：本地评审分对「语义硬伤」存在系统性盲区——人工试读连续翻车的四类问题（人称漂移、称谓/关系张冠李戴、题材内容塌陷、设定编造）机器分全给高分。必须在投稿前加独立关卡，且前四关必须是零成本纯规则，才能每章无脑跑。

| 关卡 | 检测内容 | 实现 | 成本 |
|---|---|---|---|
| 1 | 同章人称视角切换（带证据句） | `qa_semantic_check.detect_pov_shift` | 零 LLM |
| 2 | 称谓簇区间断裂 / 主角换名接管 | `detect_name_drift` | 零 LLM |
| 3 | 题材内容塌陷（标题词 vs 正文题材密度） | `detect_genre_content` | 零 LLM |
| 4 | 人物关系张冠李戴（排他型关系指向冲突） | `detect_relation_drift` | 零 LLM |
| 5 | 设定/数字编造核查（对照跨章硬状态） | `novel_pipeline.run_fact_check`：规划官 glm 链与写手**异家族**独立核查，落 `type=fact_check`；预算 `FACT_CHECK_BUDGETS=(8000, 16000)` 逐档重试（防思考链吃满致静默失效） | 1 次 LLM/章（最多重试 1 次） |

- 关卡 5 开关 `--no-fact-check`（默认每章开启）；**核查执行失败必须记 `error` 且不作为通过凭据**，门禁据此判 FAIL——不能把「没跑成」当成「没问题」。**命中即治理（2026-09-26，缺陷 #14）**：`fact_check_stage`＝核查 → 命中即 `fact_fix_prompt` 定点修 → 复检，**只有复检命中数下降才采纳、否则回滚**；台账口径始终是前章（修完不回灌自证）。写手侧同步加【事实与数字硬约束】预防（数字只准取自台账，背景细节首次出现须在本章交代来龙去脉）
- **世界观专名清单注入**（治第 13 项「世界观未落地」）：`fanqie_review.world_consistency` 给出 `missing` 清单 → ① 写手 `scene_prompt(world_terms=…)` 逐场景要求「带出 N 个（N = min(2, 池长)，全章 min(4, 池长)）、按字面照抄」；② 定点修 `fix_prompt(review, content, world_terms)` 增「【世界观专名·本条为阻断项】」区块，点名缺哪几个、至少补几个，并禁止列清单/整段解释设定；③ 门禁第 13 项失败明细带「专名 X/Y：缺 …」。Dart 端 `FanqieGateReport.worldMissing` + `fixPrompt` 同口径（见「三·九」末行）
- **专名池抽取口径**：`extract_world_terms` ＝ 引号/书名号内片段（可 2 字）＋ 按分隔符切片且 ≥3 字的片段，上限 14 个；分隔符已含全角 `／` `｜`。**已知覆盖缺口**：未加引号的 2 字设定（如境界链「蕴尘→聚象→灵枢…」）不入池，见「七、已知问题」
- **冒烟门禁十六项**（`scripts/run_smoke_gate.py`，按输出顺序）：①JSONL 结构完整 ②章节数达标 ③日志无 Traceback ④编辑链无过度压缩告警 ⑤各章评审分有效（0 分＝静默失效）⑥评估卡非空 ⑦终审卡含合并终分 ⑧成书 txt 生成 ⑨末尾完整收句 ⑩无指令/元话语残留 ⑪无章内大段重复 ⑫无题材漂移 ⑬无阻断级硬伤章 ⑭语义三关无硬伤 ⑮关系无张冠李戴（关卡4）⑯编造核查通过（关卡5：全覆盖＋无编造＋无执行失败）
- 项数轨迹：八项（初建）→ 十二项（2026-09-16）→ 十五项（2026-09-23，+关卡4）→ **十六项（2026-09-26，+关卡5 编造核查）**
- 低分章只 WARN 不误伤（评审分低于 `--review-pass` 不算回归）；但第 4 项「过度压缩」虽属 WARN 语义仍计入结果，目的是让编辑链异常在报告里始终可见。**根治（2026-09-26，缺陷 #13）**：定点修提示词补 `FIX_MIN_RATIO=0.92` 字数下限与「压缩诉求让位于下限」条款——此前提示词只有「删水段/25 字句/3 行段」三条压缩指令，模型照做必然跌破 0.85 守卫 → 4 次产出全被拒、定点修白跑；加严后守卫从常触发的闸退回安全网

### 3. 断点续传（重要）

- 同命令重跑即自动续跑：已完成章节跳过、伏笔台账/跨章状态/评审记录/打回重写补丁自动恢复
- **续传判断以 jsonl 落盘为准，不以日志/终端显示为准**（进程可能"退出码 0"假死、日志可能滞后）
- nohup 后台跑在 Windows 上**挡不住系统休眠**：长跑书请关闭休眠或用计划任务/watchdog 守护

参数：`--output`（产物路径，默认 `data/generated/smoke_gate.jsonl`；历次门禁按 `smoke_gate_v2…v7` 逐轮改名存档，须显式传 `--output`）、`--total-words` 6000、`--max-chapters` 3、`--genre`（题材漂移检测须按题材判定）、`--check-only`。流水线进程退出码非 0 时**禁止沿用旧产物继续验收**，直接判 FAIL。门禁退出码非 0 即未过，验收日志以侧车形式落 `<产物>.smokegate.log` 供追溯。

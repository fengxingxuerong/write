## 一、项目概述

墨匠是多模型协作的长篇小说生成流水线：不同 LLM 各司其职（规划/写作/编辑/标题/审校/终审等），配合本地零成本质检（番茄评审器、黄金三章体检、爽点曲线、签约可行性报告），从大纲到成书全链路自动推进，支持断点续传与质量闭环。

**核心目录**：
- `scripts/novel_pipeline.py` —— 多角色协作流水线主程序（本次交付主改动文件）
- `scripts/generate_novel.py` —— 单模型生成器 + 共享函数库（prompt/质检/JSON 解析）
- `scripts/fanqie_review.py` —— 番茄过审评审器（本地规则，零 LLM 成本）
- `scripts/qa_scan_existing.py` / `ab_compare.py` / `run_quality_test.ps1` —— 成书扫描 / A/B 对比 / 一键实测
- `scripts/probe_roster_20260912.py`、`probe_roster_r2_20260912.py` —— 端点花名册探针（两轮）
- `scripts/smoke_roles_20260912.py` —— 8 角色矩阵冒烟测试
- `data/generated/` —— 成书产物（jsonl 进度 / txt 成书 / 评估卡 / 终审卡 / 上架包）

## 三、终审官：三级质量权力（本次核心交付）

收官后 Phase 3.5 自动执行，流程：

```
终审第 1 轮（pro 通读：全书结构化摘要 + 首章/末章/最低分章样本正文）
   ↓ 总分 < 打回线（默认 75，--chief-rewrite-threshold）
【权力一·修章】从 top_issues 提取被点名章节（≤ --chief-rewrite-max 章，默认 3）
   → 编辑链定向重写（问题+证据+修改方向注入，只修问题不动剧情，字数只多不少）
   → 该章重新评审并同步分数
   ↓
终审第 2 轮（二审，以其为准；重写后总分仍会如实给低分，不放水）
   ↓ 二审仍 < 打回线（且 --no-chief-structure 未开）
【权力二·结构打回】交规划官裁决（structure_fix_prompt）
   → 规划官增补收尾章（≤ --chief-structure-max 章，默认 2）
   → generate_appended_chapter 走完整角色链生成（规划→写手→编辑→标题→评审门→状态/伏笔）
   → 终审第 3 轮确认，终审卡记录完整轨迹
```

- 输入证据包：逐章指标表（字数/评审分/钩子/AI味/问题数）+ 跨章状态清单 + 未收伏笔台账 + 三段样本正文
- 输出：JSON 总评（总分 / 六维：开篇钩子·节奏曲线·人物弧光·爽点与期待感·伏笔回收·结局力度 / 带证据问题清单 / 可执行修改建议 / 商业对标）
- 解析鲁棒性：严格失败自动修复解析；规划官裁决解析失败自动重试一次，**绝不把解析失败误报成"判定无需加章"**
- 产物：`<书名>.终审卡.txt`（终审轨迹含修章轮次与结构轮次）+ jsonl `type=chief_review`

**结构打回真书验证（《断脉逆命诀》，2026-09-13）**：第 1 轮 71 分 → 规划官裁决「6 条核心伏笔全悬空，需补章」→ 增补第 7 章《玉裂藏珠》3292 字（评审 84 分达线）→ 三审 64 分。**机制全程跑通，但暴露指令执行衰减**：写手未兑现"回收至少 2 条伏笔"指令（章末写成开脉突破悬念，台账 6 条仍全 open）。已落地「回收清单打勾」v1 治理（必兑现清单注入 + 逐条校验 + 未兑现定向补写，单测 3 项 PASS，真书验证待配额恢复），详见已知问题。

## 三·五、大纲终审官：写前守门（第 11 角色，同日晚间新增）

**动机**：终审官二审（《断脉逆命诀》）证明结构级问题（第 1 章伏笔全悬、末章停"前夕"无结局）单章重写治不了——根子在上游大纲，等收官才发现为时已晚。守门前置到写第 1 章之前，成本一次性、收益全书级。

```
Phase 1 规划官出大纲 → concretize_world → 原始大纲落盘（崩溃恢复依据）
   ↓
Phase 1.5 大纲终审官（pro K2 主 → glm K1 备，max_tokens 8000）
   ├─ pass ✅ → 放行，进入逐章生成
   ├─ fail ❌ → 采纳修订版大纲（字段兜底合并 + 再过 concretize_world）
   │            → 修订版以新一条 type=outline 追加（load_state last-wins，续传安全）
   └─ LLM 挂/解析失败 → 放行原大纲（守门岗不阻塞生成）
```

- **检查清单**（真实成书教训沉淀为硬规则）：伏笔分布（单章新埋 ≤2、第 1 章限 1-2 条、总数 ≤ 章节数×0.8）、末章必须有结局（禁"前夕态"）、单章新设定 ≤2 个、钩子链类型不连续重复、主线动机-目标-障碍-代价闭环、无连续 2 章纯铺垫塌陷
- **审查留痕**：`type=outline_review`（pass/overall/issues/adopted）写入 jsonl
- **开关**：`--no-outline-review` 跳过守门（默认开启）
- **验证**：py_compile 通过；符号冒烟 4 项全过（链路结构/setup_keys/prompt 生成/argparse）；待下一本新书跑 Phase 1 真书验证守门出分与修订采纳

## 三·六、读者官 + 评审-质检对齐（第 12 角色，同日晚间新增）

**动机**：12 角色此前全是生产侧，无消费侧视角——终审官抓到的「第 5 章评审 100 分但钩子无」正是生产侧自嗨产物（本地评审器评分体系里根本没有钩子项）。

**读者官（READER_PROXY，dsf-flash K3，每章 1 次）**：
- 每章末尾以追读读者身份答三问：**追不追（追/犹豫/弃+原因）｜哪里想划走｜下一章最想看到什么**（纯文本 3 行，非 JSON）
- 反馈注入下一章场景规划（与跨章状态、未收伏笔同通道）——场景规划直接回应读者期待、避开弃点
- 续传：`type=reader_feedback` 落盘，`load_reader_feedback` last-wins 恢复；`--no-reader-proxy` 可关；失败空过不阻塞

**评审-质检对齐**：
1. 本地评审器（`review_chapter`）新增 `has_hook` 参数：明确无钩子 → 「重写」级问题扣 8 分，进定点修链路（None=旧调用行为不变）；流水线三处评审调用全部传入 `has_ending_hook` 结果——「100 分无钩子」从此不可能
2. LLM 审校（每 3 章）prompt 注入本地质检证据（钩子命中/爽点密度），要求评分与证据对照不得矛盾（Dart 侧待下轮双端同步）

**验证**：py_compile 通过；符号冒烟 4 项全过（同文本有钩 68 分/无钩 60 分且出重写级问题、旧路径不变、续传恢复正确）；待真书验证

- **deep_ai_metrics 新增三项**：比喻密度（明喻强结构+独词正则）/ 单句成段占比（≤14 字段占比）/ 身体反应密度（19 词表）——**经四本真实成书回测校准**（比喻 2.0 对齐 prompt 承诺线、单句段 30%、身体反应 1.5）
- **level 保守并入**：三项中 ≥2 项超标才 level+1（0-4 → 0-5，判定线 ≥3 不变），旧消费方零改动

## 四、使用指南

### 1. 环境准备

密钥在 `.env.local`（已 gitignore，不入库），变量名固定：
`NOVEL_KEY_AMD` / `NOVEL_KEY_SENSE_K1` / `NOVEL_KEY_SENSE_K2` / `NOVEL_KEY_SENSE_K3` / `NOVEL_KEY_NVIDIA` / `NOVEL_KEY_OPENROUTER`

```bash
# Git Bash 启动方式
cd /d/novel-writer
set -a; source .env.local; set +a
python -u scripts/novel_pipeline.py \
  --total-words 18000 --max-chapters 6 --genre 玄幻 \
  --output "D:/novel-writer/data/generated/<书名>.jsonl"
```

### 2. 关键参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--total-words` / `--max-chapters` | 100000 / 40 | 目标字数 / 章数上限 |
| `--genre` | 玄幻 | 题材（影响质检词表与开场约束） |
| `--chief-rewrite-threshold` | 75.0 | 终审打回线 |
| `--chief-rewrite-max` | 3 | 单轮打回重写章数上限 |
| `--no-chief-review` | 关 | 收官跳过终审 |
| `--no-chief-rewrite` | 关 | 终审不达标也不打回重写 |
| `--no-outline-review` | 关 | 跳过大纲终审官写前守门（省配额时用） |
| `--no-reader-proxy` | 关 | 跳过读者官每章追读反馈 |
| `--skip-amd` | 关 | AMD 持续限流时跳过其链路 |

### 3. 断点续传（重要）

- 同命令重跑即自动续跑：已完成章节跳过、伏笔台账/跨章状态/评审记录/打回重写补丁自动恢复
- **续传判断以 jsonl 落盘为准，不以日志/终端显示为准**（进程可能"退出码 0"假死、日志可能滞后）
- nohup 后台跑在 Windows 上**挡不住系统休眠**：长跑书请关闭休眠或用计划任务/watchdog 守护

### 4. 产物清单（output 为 `<书名>.jsonl` 时）

| 文件 | 内容 |
|---|---|
| `<书名>.jsonl` | 全量进度（大纲/章节/评审/状态/伏笔/终审，断点续传依据） |
| `<书名>.txt` | 成书正文 |
| `<书名>.评估卡.txt` | 本地规则番茄过审评估（逐章分数/问题/红线） |
| `<书名>.终审卡.txt` | 终审官 LLM 通读总评（总分/六维/轨迹/建议） |
| `<书名>.上架包.txt` | 书名/简介/标签 |
